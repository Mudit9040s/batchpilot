BatchPilot User Guide

BatchPilot is the safe gateway between spreadsheets and APIs. Upload an Excel/CSV, let it validate every row, see the exact JSON that will be sent, push it in batches with username/password auth, and download a per-row Excel report of what the API accepted or rejected — all from a browser, no coding needed.

⏱️ ~2 min per upload 👥 Non-coders + Admins 🌐 Works in any browser 🧪 Safe Playground included
✅
Validates before sending Missing values, bad emails/phones, duplicates, wrong formats — flagged per row, nothing sent until you approve.
🔍
Shows the JSON The exact request body is displayed before and after sending — per batch and per row.
📊
Per-row outcome report Downloadable Excel with original data + validation flags + the API's accept/reject verdict for every row.

🔐 Signing In

The portal is protected by a username/password login page.

Open the portal URLShared by your admin, e.g. https://batchpilot-xxxx.onrender.com
Enter your credentialsUsername and password are set by the admin (not your FieldAssist login).
You land on New UploadSessions last 12 hours; use Sign out (top-right) on shared computers.
⚠️ Wrong password? Credentials are set by the admin via environment variables — contact them; there is no self-service reset.

Step 1 · Choose Where the Data Goes

Pick your file first (row 1 must be column headers), then choose one of three destinations.

ModeUse whenWhat happens
🧪 PlaygroundLearning or demoing the toolSends to a built-in fake API. 100% safe — nothing real is ever touched. It deliberately rejects bad rows so you can see how failures look.
🔗 Custom APIPushing to any real API ad-hocYou type the API URL, username, password, batch size. Requires an extra confirmation before sending.
📁 Saved profileRecurring, pre-approved uploadsPick a pre-configured destination (e.g. FieldAssist outlet update) — no URLs or credentials to type.
💡 First time? Run the Playground once with sample_data/customers.xlsx. Row 2 is intentionally broken — you'll see validation, partial acceptance, and the report in 60 seconds.

Step 2 · Custom API Setup

User Flow

Everything the base automation script needed — now as form fields.

FieldRequiredDescription
API endpoint URLRequiredFull https://… address of the bulk API. Internal/private addresses are blocked for safety.
MethodRequiredPOST (default), PUT, or PATCH.
Batch sizeRequiredRows per request (default 100, max 2000). FieldAssist bulk APIs accept up to 2000.
Delay between batchesOptionalSeconds to pause between requests (default 1s) — keeps rate limits happy.
API username / passwordRequiredSent as HTTP Basic auth. Used only for this upload — never stored.
Send values as textToggle (on)Every value becomes a trimmed string, blanks become null — identical to the original script's behaviour. Recommended for FieldAssist.
Wrap records in a keyAdvancedLeave blank = body is a bare JSON array [{…},{…}] (default, matches the base script). Enter a key to send {"key": […]} instead.
Response mappingAdvancedTells BatchPilot how to read per-row results from the API's response. Leave defaults if unsure.

Step 3 · Column Mapping (optional)

The moment you pick a file, BatchPilot reads its header row in your browser and fills the Advanced: map file columns → API field names table automatically.

Left column = your file's headersPre-read automatically from the xlsx/csv.
Right column = the name the API expectsEdit freely, e.g. Cust Name → customerName.
Blank = skipClear a field to exclude that column from the upload entirely (e.g. internal notes).
💡 If your headers already match the API's field names exactly, skip this section — unchanged names pass through as-is.

Step 4 · Validation Review

Click Validate file. Nothing is sent yet — you land on the review page.

🔴
Errors (red rows)Missing required values, invalid emails/phones, non-numeric quantities, out-of-range values. Held back by default when sending.
🟡
Warnings (yellow rows)Duplicates, over-length text. Sent anyway — but flagged for your judgement.
🟢
Clean rowsMarked ✓ clean. Ready to go.

The four tiles at the top summarize: total rows, rows with errors, rows with warnings, and batch size.

Step 5 · JSON Preview

The "JSON being sent" panel shows the exact request body the API will receive — bare array or wrapped, stringified or typed, first records of the first batch — plus the endpoint it goes to.

[
  {
    "ProductERPId": "SKU-1001",
    "Price": "249.50",
    "MRP": "299.00"
  },
  ...
]

Need row-level detail? Every row in the table has a { } toggle that expands to that row's individual JSON.

✅ What you see is byte-for-byte what gets sent. If the JSON looks wrong, fix the mapping or the file — before anything leaves the building.

Step 6 · Send & Confirm

Hold back rows with errorsTicked by default — broken rows stay behind, clean rows go.
Confirmation checkbox (Custom API only)"I understand this sends real data to <endpoint>" — required before the button works.
Click SendBatches go out with your batch size, delay, and automatic retry on server errors (429/5xx). Double-clicks and duplicate tabs are guarded — a job can only be sent once.

Step 7 · Results & Excel Report

After sending, every row shows its individual verdict.

OutcomeMeaning
✓ acceptedThe API accepted this row.
✗ rejectedThe API refused it — the reason (e.g. "Beat not found", "Duplicate ErpInvoiceNo") is shown inline.
— held backNever sent, because it had validation errors and "hold back" was ticked.

⬇ Download Excel report gives you a color-coded workbook: original data + validation flags + API status + API message, one row per row. Share it, fix the failures, re-upload just those.

⚠️ Partial acceptance is normal. APIs like FieldAssist can accept 950 of 1000 rows. BatchPilot maps each per-record result (keyed by ERP ID) back to your original spreadsheet rows.

📦 JSON / ZIP Invoice Workflow

For pre-built JSON payloads (like DMS invoices), skip spreadsheets entirely.

Upload a .zip of .json filesOr a single .json (object or array). Each file/entry = one API request.
Review the file listEach payload shows its top-level keys; broken JSON is flagged red before anything is sent.
SendOne request per payload, 0.3s apart (DMS profile), with retry. Per-file ✓/✗ plus the API's error text, and the same Excel report.
💡 This replaces the "GRN Update" Colab notebook: same behaviour, plus validation, audit history, and a report — and credentials stay out of the code.

🕘 Job History

Every upload — by any user — is logged. Click a job ID to reopen its full review/results page and re-download its report. Columns: file, profile, rows, errors, status (validated/sent), accepted count, and whether AI validation ran.

Copy a templateprofiles/example-real-api.yaml → profiles/my-api.yaml
Fill in the API contractendpoint, method, headers/auth (env vars), records_key ("" = bare array), batch_size, delay.
Declare field rulesrequired / type (email, phone, number, date) / regex / min–max / unique per column.

Commit & pushThe profile appears in the dropdown automatically after redeploy (~3 min).

📋 Key Notes & Considerations

😴
Free hosting sleepsAfter idle time the first visit takes ~30–60s to wake. Job history resets when the server restarts — downloaded reports are yours forever.
1️⃣
One send per jobA job can only be sent once — re-upload the file to send again. Double-clicks are guarded.
👥
Multi-user safeSimultaneous uploads by different people don't interfere; each job is isolated.
🧪
Test small firstBefore any real bulk push, send a 2–3 row file and check the per-row results.
🔐
Credentials are per-uploadCustom API usernames/passwords are used for that job's requests and never written to disk.
📅
Whole-batch vs per-rowIf an API returns no per-record detail, all rows in a batch share one outcome — the report says which.
